# BUILD: AI JOB AGENT — LOCAL-FIRST AUTONOMOUS JOB SEARCH & APPLICATION SYSTEM

## ROLE

You are the lead software architect and engineer building a production-quality MVP called **AI Job Agent**.

The system is a personal AI-powered job discovery, matching, application preparation, and application-tracking platform.

The system will initially run on the user's Windows PC when the PC is turned on.

Build the system in a way that can later be migrated to a VPS/cloud environment without major architectural changes.

IMPORTANT:

- Build real functionality, not mock/demo screens.
- Do not generate fake job data and present it as real.
- Do not pretend an application was submitted when it was not.
- Do not hard-code API keys.
- Do not hard-code the user's personal information.
- Do not implement arbitrary CAPTCHA bypassing, anti-bot bypassing, or authentication bypasses.
- Use official APIs or permitted/public interfaces wherever available.
- For sites requiring browser interaction, use Playwright in a controlled manner and respect site restrictions.
- Keep human approval available for applications.
- Never fabricate candidate qualifications or answers.
- Never apply to the same real-world job twice.

---

# 1. PRIMARY OBJECTIVE

Build a local-first application that can:

1. Load and analyze the user's CV.
2. Build a structured candidate profile.
3. Allow the user to configure OpenAI and Google Gemini API credentials.
4. Allow the user to select/configure AI models.
5. Discover jobs from configured sources.
6. Normalize job information.
7. Detect duplicate jobs across multiple sources.
8. Match jobs against the candidate profile.
9. Score jobs.
10. Generate tailored application materials.
11. Prepare applications.
12. Send email applications through Gmail OAuth where appropriate.
13. Support browser-based application workflows where permitted.
14. Allow human approval before submission.
15. Optionally enable automatic applications based on configurable rules.
16. Track every application.
17. Monitor Gmail for recruiter responses.
18. Detect interview invitations and other application events.
19. Maintain an immutable-style application history/audit trail.
20. Never submit the same real-world job twice.
21. Run automatically when the local machine starts.
22. Continue processing jobs while the application is running.
23. Pause safely when AI providers or external services are unavailable.

# 12. DUPLICATE DETECTION — CRITICAL

THIS IS A CORE REQUIREMENT.

The system must NEVER apply to the same real-world job twice.

Do not rely only on URLs.

Create a deterministic job fingerprint using normalized:

- company
- title
- location
- description
- external job ID where available

Use SHA-256 or equivalent.

Database constraint:

job fingerprint must be unique.

Also create semantic duplicate detection as a secondary mechanism.

Example:

LinkedIn:
"Frontend Developer — ABC Ltd"

Company website:
"React Frontend Developer — ABC Limited"

Indeed:
"Frontend Engineer — ABC Ltd"

These may be the same job.

The system must flag potential duplicates.

Use deterministic matching first and AI semantic matching second.

Application records must enforce one application per canonical job.

Even if the same job appears on 10 websites, it must result in at most ONE application.
